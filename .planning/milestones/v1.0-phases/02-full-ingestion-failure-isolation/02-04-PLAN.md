  <action>
Create `src/lib/pipeline/truncateSummary.ts` exporting two symbols and nothing else.

`SUMMARY_MAX_CHARS`, a `const` equal to `400`. Document the number's derivation in a comment on
the constant: the card's widest desktop measure is the `max-w-4xl` page column (896px) less the
card's own horizontal padding (24px each side), giving roughly an 848px text column; at the
summary's 16px `text-base` size that is roughly 105-110 characters per line, so three lines hold
roughly 318 characters. 400 sits deliberately above that, which makes the component's three-line
clamp — not this cap — the bound the reader actually perceives on every viewport. The cap's job
is different and narrower: keeping a publisher body measured live at 26,744 code points out of
the RSC payload, a roughly 98.5% reduction in the worst case. State that these two bounds are
complementary, not redundant, so neither is later removed as "the duplicate one".

`truncateSummary(text: string): string`, a pure function with no I/O, no dependency, and no
awareness of which source produced the text. Implement it as follows.

Measure length in Unicode code points, not UTF-16 code units — build a code-point array from the
input with `Array.from` (or spread) and use its length. If that length is at or below
`SUMMARY_MAX_CHARS`, return the input unchanged: no marker, no reallocation, no trimming beyond
what `normalize.ts` already did. This branch is what keeps the existing `normalize.test.ts`
expectations passing byte-identically.

Otherwise, take the first `SUMMARY_MAX_CHARS - 1` code points from that array and rejoin them.
Reserving one code point for the marker is what makes the cap an absolute ceiling and makes the
function idempotent — its own output is at most `SUMMARY_MAX_CHARS`, so a second application
returns it untouched. Add a comment saying so, because a later reader will otherwise "simplify"
the minus-one away and silently break idempotency.

Then find the last whitespace position in that slice. If one exists at or beyond 60% of the cap,
cut there; otherwise keep the hard cut. The 60% floor is what stops a pathological input whose
only whitespace sits near the very start from collapsing a 400-code-point budget down to a
handful of words — state that reasoning in a comment. Apply `trimEnd` to the result, then strip
any trailing run of comma, semicolon, or colon characters, then append the single horizontal
ellipsis character (U+2026) — one character, not three periods, and no space before it.

Never slice the raw string by index. Indexing into the UTF-16 string directly is precisely how a
surrogate pair gets split into a lone surrogate, which would put an ill-formed string into the
payload; operating on the code-point array is the whole reason that array is built.

Create `src/lib/pipeline/truncateSummary.test.ts` using `node:test` and `node:assert/strict`,
importing from `./truncateSummary.ts` with the explicit extension this repo uses. Write one
`test()` per item in the behaviour list above, eight in total. Build the over-cap fixtures from
`SUMMARY_MAX_CHARS` arithmetic rather than from hard-coded literal lengths, so the suite keeps
proving the invariant if the constant is ever retuned. For the well-formedness case, assert with
`String.prototype.isWellFormed()` on the result and also assert its code-point length is within
the cap — length alone would pass for a string that had been cut mid-pair. For the word-boundary
case, assert that the input starts with the result minus its final character, which is a stronger
and more diagnostic claim than merely asserting a space is present. For the idempotency case,
assert strict equality between one application and two.

Finally, wire it into `src/lib/pipeline/normalize.ts`: import `truncateSummary` and wrap the
existing summary expression in a call to it, so the already-trimmed publisher snippet is capped

the card's primary affordance, so bounding it visually is sufficient.

Add two cases to `src/lib/pipeline/normalize.test.ts` without editing any existing test: one

second is the wiring proof — the unit suite proves the function, this proves it is actually
