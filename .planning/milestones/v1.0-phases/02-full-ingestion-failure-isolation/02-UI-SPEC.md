## Typography

Carried over unchanged from Phase 1's shipped code — this phase introduces no new text roles or sizes, only new badge *colors* (see Color below):

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (summary) | 16px (`text-base`) | 400 (regular) | 1.625 (`leading-relaxed`) |
| Label (source name, badge, meta time, masthead) | 14px / 12px (`text-sm` / `text-xs`) | 500 (`font-medium`) | 1.5 default |
| Heading (article title) | 20px (`text-xl`) | 600 (`font-semibold`) | 1.375 (`leading-snug`) |

4 distinct px sizes (12/14/16/20) across the 3 roles above. 3 distinct CSS `font-weight` values are in use (400, 500, 600), but they map to only **2 design roles** — regular (400, body copy) and emphasis (500/600, labels and heading) — inherited unchanged from Phase 1's shipped code and justified by needing body/label/heading contrast within a conservative, no-component-library palette. This phase does not touch typography; recorded here only so the contract is complete for the checker.

## Color

Dominant/secondary/destructive are unchanged from Phase 1. The only color decision this phase makes is the 5-color badge-palette extension (D-01–D-04), broken out in its own table below because it is the actual deliverable, not a single "accent" token.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` light / `#0a0a0a` dark (`--background`, `bg-white` / `dark:bg-zinc-900` on cards) | Page background, card surface |
| Secondary (30%) | `zinc-200` / `dark:zinc-800` borders, `zinc-500`/`zinc-600`/`zinc-700` text tiers | Card borders, source name, summary text, masthead label |
| Accent (10%) | See **Tier Badge Palette** below — 6 distinct hues, none dominant | Reserved exclusively for the 6 source-tier badge pills (`SourceTierBadge.tsx`) — no other element uses accent color |
| Destructive | not applicable this phase | No destructive action exists in this phase (D-02 keeps red reserved, unused) |

Accent reserved for: the source-tier badge pill only (`<SourceTierBadge>`). Nothing else in the current UI (card border, title link, meta time, masthead) uses a hue-accent color — they stay in the zinc/white neutral scale. Red and orange are excluded from every accent use (D-02), kept free for future CVE-ID chips (Phase 3) and urgency cues (Phase 4).

### Tier Badge Palette (D-01–D-04)

All 6 pills share one shape/size/weight (`rounded-full px-2.5 py-0.5 text-xs font-medium`, D-03) — color is the *only* differentiator, and none of the 6 carries semantic rank (D-01: color differentiates, it does not categorize by severity or trust). Every entry uses the identical Tailwind `{hue}-50 / {hue}-700 / {hue}-200` construction already shipped and verified for "Security Research" (D-04) — the -700-on-50-background pairing clears WCAG AA (4.5:1) text contrast by the same margin already confirmed for indigo, since Tailwind's 50/700 pairs are constructed with equivalent luminance deltas across its hue palette. No red or orange hue appears anywhere in this set (D-02).

| Tier | Classes | Status |
|------|---------|--------|
| Security Research | `bg-indigo-50 text-indigo-700 ring-1 ring-inset ring-indigo-200` | Locked — do not change (D-04, shipped Phase 1) |
| Government | `bg-blue-50 text-blue-700 ring-1 ring-inset ring-blue-200` | New this phase |
| Enterprise Security | `bg-teal-50 text-teal-700 ring-1 ring-inset ring-teal-200` | New this phase |
| Threat Intelligence | `bg-violet-50 text-violet-700 ring-1 ring-inset ring-violet-200` | New this phase |
| Tech & General | `bg-emerald-50 text-emerald-700 ring-1 ring-inset ring-emerald-200` | New this phase |
| Executive News | `bg-fuchsia-50 text-fuchsia-700 ring-1 ring-inset ring-fuchsia-200` | New this phase |

Implementation note for the executor: only `src/components/SourceTierBadge.tsx`'s `TIER_STYLES` map changes — replace the 5 `bg-slate-100 text-slate-700 ring-slate-200` neutral-default entries with the 5 rows above, verbatim. The component's JSX, size, and shape are untouched (D-03).

## UI Considerations

Applicable state considerations resolved: 6 covered, 1 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | combined article list | ✅ covered | Genuinely-quiet-window and all-13-sources-failed render the identical copy row above (D-06) — no new empty-state variant for this phase |
| error | per-source fetch failure | ✅ covered | Failure is invisible by design (D-05) — `getFrontPage.ts`'s swallow-and-continue contract means no error UI exists to design; a broken source and a quiet source are visually identical |

| long-text | 5 new tier-badge labels ("Enterprise Security", "Executive News", etc.) | ✅ covered | `SourceTierBadge.tsx` already sets `whitespace-nowrap` (Phase 1); new labels are the same or shorter length than the already-tested "Security Research" and wrap identically at narrow widths |
