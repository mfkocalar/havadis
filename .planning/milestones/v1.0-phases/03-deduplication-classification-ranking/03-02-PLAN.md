<objective>
Make the multi-source list trustworthy: decode HTML entities in titles once at normalization
(closing the STATE.md CrowdStrike `&trade;` blocker), then collapse the same story arriving from
several outlets into one card — matched on a canonical URL or a normalized title, earliest copy
wins, silently. This plan owns NORM-02 and implements D-01 through D-04.

**As a** security expert, **I want to** see each story once, with its headline rendered the way
the publisher wrote it, **so that** the front page is not padded with the same news from three
outlets or littered with raw `&trade;` markup.

Purpose: the decoded title is both what readers see and the dedupe input (D-04), so decoding must
land first; the dedupe stage then slots into the `composeFrontPage` seam Plan 03-01 created,
which is also what lets Task 3 prove the collapse through the whole composed pipeline without
network.
Output: `decodeHtmlEntities`, the D-04 change to `normalize`, `canonicalizeUrl`,
`normalizeTitleForDedupe`, `dedupe`, its wiring, and hermetic + composed + live tests.
</objective>

<assumption_delta_decision>
**Detector:** `gsd_run query assumption-delta scan 03 --json` returned `detected: true` with one
signal, `pluralization` on "the same story reported by multiple outlets".

**Noun now primary:** `Article` — one normalized feed item from one outlet, identified by its
`url`, which is also the React `key` in `page.tsx`. A "story" (the set of outlet items D-01
considers the same) is a transient equivalence class that exists only inside `dedupe()` while it
runs and is immediately collapsed to one surviving `Article` (D-02). It is never reified as a
type, id, or field — D-03 explicitly forbids "also reported by" data on `Article`.

**Decision: no-change.** The plural in the phase goal describes dedupe's *input*, not a new
output noun: output cardinality stays one `Article` per rendered card, so `article.url` remains
the right identity and the right React key. Canonical URL keys and normalized title keys are
internal comparison keys only and never replace the stored `url` or `title`.

**Invariant guard:** Task 3 adds a live end-to-end assertion that post-dedupe `article.url`
values are unique, and that canonical URL keys and non-empty normalized title keys are unique too,
so the key can never silently collide. Uniqueness also holds by construction: identical raw URLs
produce identical canonical keys and are merged.

**Revisit trigger:** if a later phase adopts the deferred "also reported by" note or a
multi-outlet coverage boost (D-03, D-11), promote Story to a first-class type at that point.
</assumption_delta_decision>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| external feed origin -> Vercel Function | Untrusted `title` text is now entity-decoded and used to build dedupe keys; untrusted `link` text is parsed into a canonical key. |
| Vercel Function -> rendered HTML | The decoded title crosses into a JSX text node; `article.url` crosses into an `href`. |
| pipeline stages -> `getFrontPage` never-throws contract | A throw in decoding, canonicalization or dedupe would collapse the whole page to the empty state. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-06 | Tampering (stored XSS) | entity decoding turning an encoded `&lt;script&gt;` title into literal markup characters | high | mitigate | The decoded string is only ever a plain JSX text child (`ArticleCard.tsx`), so React escapes it at render; no raw-HTML injection prop exists anywhere under `src/` (Task 1's comment-filtered `NO_RAW_HTML_SINK` gate). Task 1's tests pin that `&lt;script&gt;` decodes to the plain string `<script>`, i.e. text, and that decoding happens exactly once. |
| T-03-07 | Tampering | a canonical dedupe key replacing the displayed link and bypassing normalize's http(s)-only check (T-01-04) | medium | mitigate | `canonicalizeUrl`'s output is used only as a `Map` key inside `dedupe`; `dedupe` returns the original article objects unmodified (Task 2 asserts reference identity and an unchanged `url`), so the rendered `href` is always the value `normalize` validated. |
| T-03-08 | Spoofing | a hostile or compromised feed publishing an item with the same normalized title and an earlier `publishedAt` to displace a legitimate outlet's copy | low | accept | Sources are a fixed, curated, build-time list of 13 publishers (`sources.ts`); the attacker must control one of those feeds. Earliest-wins is the developer's D-02 product decision, the displaced story is still shown (only its attribution changes), and the surviving link still passed normalize's http(s) gate. Revisit if sources ever become runtime-configurable. |
| T-03-09 | Denial of Service | decoding and dedupe-key regexes over unbounded, feed-controlled titles | medium | mitigate | The entity pattern uses only bounded quantifiers (`{1,7}`, `{1,6}`, `{1,31}`) and the title-key regexes are single character classes, so all scans are linear; union-find is near-linear in article count. Task 1 asserts a 200,000-character input decodes in under 500 ms. |
| T-03-10 | Denial of Service | `new URL()` throwing on a malformed link inside dedupe and collapsing the page | medium | mitigate | `canonicalizeUrl` wraps parsing in try/catch and falls back to the trimmed raw string; Task 3 asserts "not a url" returns without throwing. `getFrontPage`'s single outer `try` remains as the last line of defence. |
| T-03-SC | Tampering | npm/pip/cargo installs | n/a | accept | No package-manager install task exists. The entity decoder is hand-rolled; `entities` (flagged `SUS`/too-new in 03-RESEARCH.md's Package Legitimacy Audit) is deliberately NOT installed. |
