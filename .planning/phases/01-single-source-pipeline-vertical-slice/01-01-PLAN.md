<objective>
Stand the Havadis application up from an empty repo and prove the whole Phase 1 architecture end to end with one real source: a public, unauthenticated `/` route that fetches the live Krebs on Security feed through a redirect-validating, timeout-capped fetch, caches it in Next.js's Data Cache on a 15-minute revalidation window, normalizes it to the shared `Article` shape, trims it to the last 24 hours, and renders the result.

Purpose: this is the Walking Skeleton. Every later phase widens this exact path — Phase 2 grows `SOURCES` from 1 to 13 entries, Phase 3 inserts pure transforms between `filterLookback` and render, Phase 4 restyles the render. Getting the seams right here is worth more than getting any single layer complete, which is why this plan leads with a tracer rather than building layers.

Output: a buildable Next.js 16 project whose `/` route renders real, current Krebs articles, plus a live end-to-end test that drives the whole pipeline.
</objective>

    Declare the shared contracts in `src/lib/types.ts`: `SourceTier` as a string-literal union covering the six tiers in PROJECT.md's source table (`Government`, `Security Research`, `Enterprise Security`, `Threat Intelligence`, `Tech & General`, `Executive News`) so Phase 2 can add the other twelve rows without touching the type; `SourceConfig` as `{ id: string; name: string; tier: SourceTier; url: string }`; and `Article` as `{ title: string; url: string; source: string; sourceTier: SourceTier; publishedAt: string; summary: string }` where `publishedAt` is ISO 8601.     In `src/lib/config/sources.ts` export a `SOURCES: SourceConfig[]` array with exactly one entry, per D-01: id `krebs`, name `Krebs on Security`, tier `Security Research`, url `https://krebsonsecurity.com/feed/`. Use the trailing-slash form deliberately — the bare `/feed` path that appears in PROJECT.md and CONTEXT.md 301-redirects to it, and because the Data Cache stores only 200 responses that redirect hop would be re-fetched on every revalidation cycle forever. Keep the array shape even at one entry; nothing Krebs-specific may live outside this file.

    In `src/lib/pipeline/fetchWithValidatedRedirect.ts` implement the validate-then-follow loop from PATTERNS.md, with module constants for the 8000ms per-hop timeout and the 5-hop maximum. Every request is issued with `redirect` set to `"manual"` from the first line of code — the default mode commits to following before application code sees the response, so there is no safe way to add this guarantee afterwards. On a 3xx, read the `Location` header; a missing or empty header is an error, not a success. Resolve the header against the current URL so a relative target works, then reject unless the resolved protocol is exactly `https:` and the resolved `host` string is exactly equal to the original `host`. Exact string equality on `host` is the requirement: `host` includes the port, and a suffix or domain-contains comparison would accept `sub.krebsonsecurity.com` and `krebsonsecurity.com.example.net`. Only after both checks pass does the loop advance to the validated target and issue the next request. Each hop constructs its own `AbortController` and its own timer and clears that timer in a `finally` block so an aborted hop cannot leak a timer and a chain cannot accumulate more than 8 seconds per hop. Exceeding the hop maximum is an error. Keep every value function-local — no module-scope mutable state — so concurrent callers cannot interfere.

    In `src/lib/pipeline/fetchSource.ts` implement `fetchSource(source: SourceConfig)` so that it NEVER throws: wrap the whole body and return the error variant with a descriptive `reason` on any failure. Call `fetchWithValidatedRedirect(source.url, …)` passing `next: { revalidate: 900 }` and NO `cache` option — passing the revalidate number is itself what opts the request into the persistent Data Cache, and there is no documented benefit to a second cache option alongside it. Passing an abort signal opts out of per-render memoization only; it does not disturb the persistent cache, so the 8s timeout and the 15-minute window coexist on the same call and must not be split into two fetches or shadowed by a hand-rolled TTL map. Send a `User-Agent` header (see the prohibition below for its required shape) and an `Accept` header covering `application/rss+xml`, `application/atom+xml` and `application/xml`. Treat a non-2xx status as an error. Treat a response whose `content-type` does not indicate XML as an error rather than handing arbitrary bytes to the parser. Cap how much of the body is read before parsing — a feed that streams unbounded bytes must fail rather than exhaust the function. Parse the retrieved text with the rss-parser instance's string-parsing entry point; never use the parser's own URL-fetching entry point, which drives Node's raw http client, is invisible to the Data Cache, and would silently delete the caching behaviour this whole application is built around. Map each parsed item through `normalize` and drop the nulls.

    In `src/lib/pipeline/normalize.ts` implement `normalize(item, source): Article | null` per PATTERNS.md's verbatim example, extended with one extra guard: every field arriving from the feed is untrusted external input, so in addition to returning null when `title`, `link` or `isoDate` is missing, parse `link` as a URL and return null unless its protocol is `https:` or `http:`. That guard is what keeps a hostile feed from putting some other URL scheme into an `href`. Trim the title. Prefer the HTML-stripped snippet field for `summary`, fall back to the raw content field, and fall back to an empty string — never `undefined`. Carry `source.name` and `source.tier` onto the article. Perform no sorting, no merging and no deduplication: two items with the same title and link must both survive, because collapsing them is a Phase 3 concern and doing it here would make that later change invisible.

    In `src/lib/pipeline/filterLookback.ts` implement `filterLookback(articles, hours = 24)` per PATTERNS.md. Compute the cutoff once, before the filter runs, so every article in one call is compared against a single consistent instant.

    In `src/lib/pipeline/getFrontPage.ts` implement the single orchestrator: iterate `SOURCES`, await `fetchSource` for each, apply `filterLookback` with the 24-hour default, and return the discriminated result. It must never throw. Structure the iteration so Phase 2 can switch it to a parallel fan-out over thirteen entries without reshaping the return value.

    Replace the scaffold placeholder in `src/app/page.tsx` with an async Server Component that awaits `getFrontPage()` directly — no Route Handler, no client component, no `middleware.ts`, no session or cookie read, nothing that could introduce an authentication surface. Render the returned articles as a list of linked titles with their published time; render feed-supplied text through ordinary JSX text nodes only, never through React's raw-HTML injection prop. When the result is the error variant, or holds zero articles, render a quiet one-line message stating that there are no articles from the last 24 hours, inside the page's normal structure — never a blank page and never a skeleton placeholder. The full article-card presentation, the tier badge and the masthead are Plan 02's deliverables in this same phase; this task's render is the real, working end of the traced path, not a stand-in for one.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| visitor browser → Vercel Function (`GET /`) | Untrusted request crosses here. Phase 1 consumes no query parameters, headers, cookies or body from the visitor, so the request carries no attacker-controlled input into the app. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering / Elevation of Privilege | `src/lib/pipeline/fetchWithValidatedRedirect.ts` redirect handling | high | mitigate | Issue every request with `redirect: "manual"`; resolve `Location` against the current URL; reject unless protocol is exactly `https:` AND `host` is exactly string-equal to the captured original `host`; cap at 5 hops. | T-01-02 | Denial of Service | slow or hanging feed origin consuming the Function's execution budget | medium | mitigate | Fresh 8000ms `AbortController` per hop, cleared in `finally`; `fetchSource` converts the abort into a `{ status: "error" }` result instead of an unhandled rejection, so `/` still renders. |
| T-01-03 | Tampering | oversized or non-XML response body handed to the parser | medium | mitigate | Reject non-2xx statuses; reject responses whose `content-type` does not indicate XML; cap the number of bytes read from the body before parsing. |
| T-01-04 | Tampering | feed-supplied `link` becoming an `href` with a non-HTTP scheme | high | mitigate | `normalize` parses `link` as a URL and returns `null` unless the protocol is `https:` or `http:`, so a hostile scheme never reaches the render layer at all. |
| T-01-05 | Spoofing | DNS rebinding to a same-named host after the host check passes | low | accept | Phase 1 configures exactly one hardcoded HTTPS source. | T-01-06 | Information Disclosure | error `reason` strings leaking internal detail into rendered HTML | low | mitigate | The `reason` string is consumed for the D-03 empty-state decision only; the page renders its own fixed copy and never prints the reason. |
