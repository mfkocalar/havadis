  <behavior>
    - A timestamp less than 60 seconds old returns `just now`
    - A timestamp 1 minute old returns `1m ago`; 59 minutes old returns `59m ago`
    - Exactly 60 minutes old crosses to the hours case and returns `1h ago` — not `60m ago`
    - 23 hours old returns `23h ago`
    - The function is pure with respect to its argument and reads the current time itself, so tests must inject timestamps computed relative to the moment of assertion rather than hardcoded dates
    - A future timestamp (clock skew between the source and the server is real) returns `just now` rather than a negative value such as `-3m ago`
  </behavior>
  <action>
    Implement `formatRelativeTime(isoDate: string): string` in `src/lib/formatRelativeTime.ts` following PATTERNS.md's origin implementation: difference the current time against the parsed ISO date, floor to whole minutes, return `just now` below one minute, return an `Nm ago` string below sixty minutes, otherwise floor the minutes to hours and return an `Nh ago` string. Add one guard PATTERNS.md's example does not carry: clamp a negative difference to the `just now` case, because a source's own clock can be slightly ahead of the server's and a `-3m ago` label is visibly wrong.

    Do not add a date-formatting library. The 24-hour lookback window collapses relative time to exactly three cases, which this function covers completely; a library here is dependency weight with no payoff and was already ruled out at the stack level.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| normalized `Article` fields → rendered HTML | Untrusted external text (title, summary) crosses into the DOM here. This is the boundary this plan owns. |
| normalized `article.url` → outbound `href` | A feed-controlled URL becomes a user-clickable destination. Scheme validation happens upstream in `normalize` (Plan 01, T-01-04); this plan owns the window-handoff properties. |
| visitor browser → Vercel Function (`GET /`) | Untrusted request. This plan deliberately adds no authentication, session or request-scoped read at this boundary. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-07 | Tampering | stored XSS via a feed-supplied title or summary rendered in `src/components/ArticleCard.tsx` | high | mitigate | Render every feed string as an ordinary JSX text node, relying on React's default text escaping. No raw-HTML injection prop appears anywhere under `src/components` or `src/app`, enforced by a negative grep gate in Task 2. |
| T-01-08 | Information Disclosure | `target="_blank"` handing the opened tab a `window.opener` reference and a referrer | low | mitigate | Every outbound anchor carries `rel="noopener noreferrer"`, asserted in Task 2's acceptance criteria. |
| T-01-09 | Spoofing | no authentication exists, so any visitor reads everything | low | accept | UI-06 requires the site be fully public and there is no protected resource, no user state and no write path to protect. The absence of this tier is the requirement, not a gap. |
| T-01-10 | Information Disclosure | internal failure detail (timeout reason, rejected-redirect host) leaking into rendered HTML via the empty state | low | mitigate | The page branches on the result's discriminant only and renders its own fixed copy; a negative grep gate in Task 3 asserts the `reason` string never reaches the render. |

**Canon-referral breadcrumbs (deliberately not minted as bespoke prohibitions):** feed-driven XSS and output-encoding concerns are canon, owned by `/gsd-secure-phase` and the ESLint React rule set; they are carried above as T-01-07 rather than duplicated into `must_haves.prohibitions`.
