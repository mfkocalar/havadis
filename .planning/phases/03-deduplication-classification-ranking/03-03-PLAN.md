<objective>
Surface CVE identifiers on the cards: detect CVE IDs in each article's title and capped summary,
and render up to three red, monospace, NVD-linked chips (plus a "+N" overflow chip) in the card's
meta row next to the tier badge. Then record the phase's documentation decisions and its API
coverage declaration. This plan owns UI-03 and implements D-13, D-14 and D-15, plus the D-12 and
D-01 documentation corrections.

**As a** security expert, **I want to** see at a glance which stories carry a CVE and jump
straight to its NVD entry, **so that** I can check CVSS and affected products without hunting
for the identifier inside the article.

Purpose: the CVE list is computed in the data layer (inside the `composeFrontPage` seam), and
the link is built from a validated ID in a pure, testable module, so D-14's link-integrity
guarantee is provable without rendering React.
Output: `extractCves`, the `cveChips` link/cap model, the `CveChips` Server Component, the
`cves` field on `ClassifiedArticle`, tests at every layer including the production page, the
PROJECT.md / REQUIREMENTS.md corrections, and `COVERAGE.md`.
</objective>
