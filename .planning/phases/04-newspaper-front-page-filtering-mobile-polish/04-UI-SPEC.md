# Phase 04 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Scope: UI-01 (responsive newspaper grid), UI-04 (last updated + per-section counts), UI-05 (mobile 360-390px + desktop, verified at real widths), FILTER-01 (client-side multi-select section filter). All 14 decisions in `04-CONTEXT.md` (D-01..D-14) are locked and pre-populated below. Nothing in this spec re-opens them. ## Spacing Scale

Declared values (all multiples of 4, all standard Tailwind steps):

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Scroller vertical padding `py-1` (leaves room for the 2px outline + 2px offset focus ring so `overflow-x-auto` does not clip it); emoji-to-label nothing larger than `gap-1` |
| sm | 8px | Pill-to-pill `gap-2`; filter bar vertical padding `py-2`; pill internal `gap-2` |
| md | 16px | Page gutter `px-4` (mobile); section heading to grid `gap-4`; pill horizontal padding `px-3` is 12px (multiple of 4, in-scale) |
| lg | 24px | Grid gap `gap-6` (rows and columns); gap between primary grid, overflow region and expander button `gap-6`; card padding `p-6` (unchanged); page gutter `sm:px-6` |
| xl | 32px | Main vertical padding `py-8` (mobile) |
| 2xl | 48px | Gap between sections `gap-12`; main vertical padding `sm:py-12` |
| 3xl | 64px | Not used this phase |

Exceptions:
- Touch targets below `md` (768px): filter pills and the "Show all N" button use `min-h-11` (44px) so every control clears the 44px touch guideline. At `md` and up pills drop to `md:min-h-8` (32px) for pointer use, which still exceeds WCAG 2.2 SC 2.5.8 (24px minimum).
- Pre-existing, unchanged and not to be extended: `SourceTierBadge` / `CveChips` use `px-2.5 py-0.5` (10px / 2px). New controls do NOT copy this padding; they copy the pill shape (`rounded-full`, `ring-1 ring-inset`) but use the tap-safe sizing above.
- `scroll-padding-top: 6rem` (96px, a multiple of 4) on `html` in `globals.css`. Covers the worst-case sticky bar height so keyboard focus and anchor jumps are never hidden under the bar (WCAG 2.2 SC 2.4.11).

Container (Discretion, D-03): **`max-w-7xl`** (1280px) for `<main>`, the masthead inner container in `layout.tsx`, and the filter bar inner container. All three use identical `mx-auto max-w-7xl px-4 sm:px-6` so header, bar and content align on one left edge. Rationale: at 1280px the 3-column card measure is about 394px (content about 346px); `max-w-6xl` would give about 352px cards (about 304px content), tighter on already three-line-clamped titles.

## Color

The project has no single brand accent. The page uses a neutral zinc system with categorical hues (tier badges) and one reserved signal colour (red for CVE chips). Phase 4 keeps that structure.

Effective surfaces (note: `globals.css` has an unlayered `body { background: var(--background) }` that overrides the `bg-zinc-50` utility on `<body>`, so the real page surface is white / near-black, matching the Phase 3 screenshots):

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Light `#ffffff` / Dark `#0a0a0a` (`--background`) | Page surface behind the grid |
| Secondary (30%) | Light `bg-white` with `border-zinc-200` (`#e4e4e7`) / Dark `bg-zinc-900` (`#18181b`) with `border-zinc-800` (`#27272a`) | Article cards (unchanged), masthead (`bg-white dark:bg-zinc-950`), sticky filter bar (`bg-white/90 dark:bg-zinc-950/90` + `backdrop-blur`, border-b `zinc-200` / `zinc-800`), unpressed pills and expander button surface |
| Accent (10%) | Light `zinc-900` (`#18181b`) fill with `zinc-50` text / Dark `zinc-50` (`#fafafa`) fill with `zinc-900` text | Pressed filter pills and the keyboard focus outline ONLY (see reserved-for list) |
| Destructive | not used in this phase (no destructive actions). Red stays reserved for CVE chips (Phase 3 D-15) | n/a |

Accent reserved for:
1. The pressed (`aria-pressed="true"`) state of a section filter pill (inverted neutral fill).
2. The `focus-visible` outline on filter pills and the expander button (`outline-zinc-900 dark:outline-zinc-50`).

Nothing else uses the accent. Section headings, counts, the "Updated" text and the expander button are muted neutrals, never the accent.

Colour rules carried over and enforced:
- Red and orange remain reserved (red = CVE chips only). **No urgency colour cues are added in Phase 4.** CONTEXT D-02 (Phase 2) allowed them as a future option, but no Phase 4 decision adopts one, so the contract adds none. Pressed pills use neutral inversion specifically to avoid colliding with the six tier hues (indigo, blue, teal, violet, emerald, fuchsia) or red.
- Pill states (Tailwind classes, all in-scale):
  - Unpressed: `bg-white text-zinc-700 ring-1 ring-inset ring-zinc-400 hover:bg-zinc-100 dark:bg-zinc-900 dark:text-zinc-300 dark:ring-zinc-600 dark:hover:bg-zinc-800`; count `text-zinc-600 dark:text-zinc-400`.
  - Pressed: `bg-zinc-900 text-zinc-50 ring-1 ring-inset ring-zinc-900 dark:bg-zinc-50 dark:text-zinc-900 dark:ring-zinc-50`; count `text-zinc-300 dark:text-zinc-600`.
- WCAG AA contrast (D-08 mandate, checked against these pairs): unpressed label zinc-700 on white about 10:1, zinc-300 on zinc-900 about 11:1; unpressed count zinc-600 on zinc-100 (hover) about 6.9:1, zinc-400 on zinc-800 (hover) about 5.9:1; pressed label zinc-50 on zinc-900 about 17:1, zinc-900 on zinc-50 about 17:1; pressed count zinc-300 on zinc-900 about 10:1, zinc-600 on zinc-50 about 7.5:1. "Updated" text: `text-zinc-600 dark:text-zinc-400` (zinc-600 on white about 7.6:1). The counts deliberately use zinc-600 (not zinc-500) because zinc-500 on the zinc-100 hover fill falls to about 4.4:1, below AA. Section heading and count keep the existing `text-zinc-500 dark:text-zinc-400` (about 4.8:1 and 7.2:1 on the page surface). The executor MUST re-verify these pairs with a contrast calculation in the plan's test/verify step; do not assume.
- State is never conveyed by colour alone: `aria-pressed` carries it for assistive tech, and the pressed pill differs from unpressed by a large luminance inversion, not hue.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (expander) | `Show all {N}` where `{N}` is the section's full article count (e.g. `Show all 12`) |
| Secondary CTA (collapse) | `Show fewer` |
| Filter pill label | `{emoji} {Section name} {count}` using `SECTION_EMOJI`, the literal `Section` string (e.g. `Tools/Techniques`, `Industry/Policy`) and the full (uncapped) section count. Accessible name adds a visually hidden suffix: `{Section name} {count} articles` (singular `1 article`) |
| Filter group accessible name | `Filter by section` (`aria-label`, not visible) |
| Filter result announcement (visually hidden live region, `role="status"`) | `Showing {k} of {n} sections` when k > 0 pills are pressed; `Showing all {n} sections` when none are pressed |
| Section heading | `{emoji} {SECTION}` + muted count (e.g. `VULNERABILITIES 12`); count has visually hidden suffix ` articles` (singular ` article`) |
| Last updated, post-hydration | `Updated {relative}` via `formatRelativeTime` (e.g. `Updated 4m ago`, `Updated just now`). Note: uses the existing `4m ago` / `2h ago` vocabulary, not CONTEXT D-13's illustrative `4 min ago`, so the bar matches every article card |
| Last updated, first paint / no-JS | `Updated {HH:MM} UTC` (e.g. `Updated 14:32 UTC`), deterministic from `generatedAt` |
| Last updated, hover (`title`) | Full absolute time: local time once mounted (`toLocaleString()`, same as cards); before mount, `{YYYY-MM-DD HH:MM} UTC` |
| Empty state heading | none (quiet by design, Phase 1 D-03 / Phase 2 D-06) |
| Empty state body | `No articles in the last 24 hours.` (existing string, unchanged). The filter bar is NOT rendered in this state |
| Error state | Identical to the empty state. The error variant's diagnostic `reason` is never rendered (T-01-10 / T-03-04); there is no retry control because the next visit after the ~15 minute window refetches automatically |
| Destructive confirmation | none: this phase has no destructive actions |

Not included on purpose: no "Clear filter" / "Show all sections" button (D-09: deselecting the last pill is the reset), no "nothing matches" state (D-09: unreachable), no per-card or per-section "new" labels.

## Layout Contract (UI-01, UI-04, UI-05)

Page skeleton (`page.tsx` returns a fragment; the bar sits OUTSIDE `<main>` so its background can span the full viewport width while its content aligns to the container):

```
<header>  masthead (layout.tsx, inner container max-w-7xl)
<div sticky bar>   full-bleed background, inner container max-w-7xl
<main max-w-7xl>   sections
```

Filter bar (D-11, D-12):
- Outer: `sticky top-0 z-10 border-b border-zinc-200 bg-white/90 backdrop-blur dark:border-zinc-800 dark:bg-zinc-950/90`. No shadow (matches the header's border-only treatment). The masthead above it is NOT sticky.
- Inner: `mx-auto max-w-7xl px-4 py-2 sm:px-6`.
- Below `md` (stacked): column. Row 1 = pill scroller. Row 2 = "Updated ..." text (`text-sm`, `pb-1`). Bar height about 88px.
- `md` and up: row, `items-start justify-between gap-4`. Pills container `flex-1`, wrapping (`flex-wrap`); "Updated ..." `shrink-0`, trailing edge, vertically aligned to the first pill row (`md:min-h-8 md:items-center` inline-flex). Pills wrap to 1 row at 1280px+ when they fit, otherwise 2 rows (they are about 1,220px wide in total, so expect 2 rows at most desktop widths). Worst-case bar height about 96px, which is why `scroll-padding-top` is 6rem.
- Below `md`, pill scroller is a single horizontally scrollable row: `flex flex-nowrap gap-2 overflow-x-auto py-1 -mx-4 px-4 sm:-mx-6 sm:px-6 md:mx-0 md:flex-wrap md:overflow-visible md:px-0` plus a `scrollbar-none` utility defined once in `globals.css` via `@utility` (hides the scrollbar below `md` only via `max-md:scrollbar-none`). The negative-margin bleed lets pills scroll edge-to-edge instead of clipping 16px inside the screen edge. The clipped third pill is the intentional scroll affordance: at 360px exactly two full pills fit, a third is visibly cut off.
- Each pill: `inline-flex shrink-0 items-center gap-2 rounded-full px-3 min-h-11 md:min-h-8 text-sm font-medium whitespace-nowrap` plus the state classes from Color. `shrink-0` so pills never squash in the scroller.
- Pills render only for **non-empty sections**, in `SECTION_DISPLAY_ORDER`, derived from the same `sections` array the page renders. A pill for an empty section would filter to nothing, which D-09 says must be unreachable.

Section (D-01, D-02, D-04, D-14):
- `<section data-section="{Section}" aria-labelledby="{heading-id}" className="flex flex-col gap-4">` (keeps the existing `data-section` attribute that `test/productionPage.test.ts` asserts).
- `<h2 id>` keeps `text-sm font-semibold tracking-wide text-zinc-500 uppercase dark:text-zinc-400`, emoji `aria-hidden`, plus the muted count span.
- Below the heading, one wrapper `flex flex-col gap-6` containing, in order: primary grid, overflow region, expander row. (Single 24px rhythm so a section reads the same collapsed and expanded; the 16px heading gap stays on the outer section.)
- Grid (primary and overflow use the identical class string): `grid grid-cols-1 gap-6 md:grid-cols-2 lg:grid-cols-3`. `ArticleCard` is the direct grid child and stretches to equal row height by default; do not wrap it in an element that breaks stretching, and do not add `h-full` wrappers.
- Sparse sections (1 or 2 cards): leave the empty cells (D-04). No `col-span`, no stretch-to-fill.
- Sections stay separated by `gap-12` in the existing `flex flex-col` list wrapper.

Expander (D-05, D-06, D-07):
- Constants (single source of truth, `src/lib/config/frontPageLayout.ts`): `SECTION_CARD_CAP = 6`, `MIN_HIDDEN_TO_COLLAPSE = 3`.
- Rule (Discretion, D-06): a section of `total` articles is capped to 6 + expander only when `total - 6 >= 3`, i.e. `total >= 9`. Totals 1-8 render every card and no expander (7 would hide 1, 8 would hide 2). Implement as a pure function `planSectionCap(total)` returning `{ visibleCount, hiddenCount }` with a colocated `*.test.ts`, matching the project's one-pure-function-per-stage pattern.
- The first 6 ranked cards render in the primary grid; cards 7..N render in a second grid (same classes) inside the overflow region. Ranking order is untouched; the cap always keeps the highest-ranked 6.
- All cards are in the initial server-rendered HTML. The overflow region is hidden with the `hidden` attribute while collapsed (no conditional rendering, no unmount), so nothing is fetched and the full list stays in the document for crawlers (D-07). The overflow region element carries no `display` utility so the `hidden` attribute is not overridden.
- Expander button sits below the grids, `w-full md:w-auto`, centred on `md` and up (`self-center`), neutral outline style: `inline-flex min-h-11 items-center justify-center rounded-full px-4 text-sm font-medium ring-1 ring-inset ring-zinc-400 text-zinc-700 hover:bg-zinc-100 dark:ring-zinc-600 dark:text-zinc-300 dark:hover:bg-zinc-800` plus the shared focus-visible outline. It is neutral (not the accent): expanding is not a selected state.
- No expand/collapse animation and no smooth scrolling anywhere in this phase (satisfies `prefers-reduced-motion` by having nothing to reduce).

## Interaction Contract (FILTER-01)

| Interaction | Behaviour |
|-------------|-----------|
| Toggle a pill | Flips that section in/out of the selected set. Multi-select. Applies instantly: no debounce, no network, no navigation. Native `<button type="button" aria-pressed>` (Enter and Space toggle) |
| No pills selected | All non-empty sections visible (D-09) |
| Some pills selected | Only selected sections visible; all others hidden |
| Last pill deselected | Returns to all sections visible |
| Order | Visible sections always stay in urgency order; selection order is irrelevant |
| Hiding mechanism | Each section is wrapped in a client visibility wrapper that renders `<div hidden={...}>`. Sections are hidden, never unmounted or conditionally rendered, so expander state survives pill toggles (Discretion: expander state persists across filtering) and all markup stays in the HTML. The wrapper div has no display utility |
| Expander vs filter | Each expander's open/closed state is independent and preserved when its section is filtered out and back in. Filtering to a single section does NOT auto-expand it |
| Persistence | None (D-10): in-memory React state only. No URL query sync, no `localStorage`/`sessionStorage`, no cookie. Reload resets to all sections. The page stays fully cacheable: the client code must not call `useSearchParams`, `cookies()` or `headers()` |
| Scroll after a filter change | Only when the bar is currently stuck (page scrolled past the masthead): scroll so the first visible section heading sits just below the bar (`scrollIntoView({ block: "start" })`, instant, relying on `scroll-padding-top`). Skip on initial mount. Prevents landing at an arbitrary offset after a long page collapses |
| Expander press | Toggles the overflow region; button `aria-expanded` and `aria-controls` (id from `useId()`) wired to the region; label switches between `Show all {N}` and `Show fewer`. On collapse, call `scrollIntoView({ block: "nearest" })` on the button so the page does not jump away from the section |
| Last updated | Client component. First render (server HTML and hydration) outputs the deterministic UTC string so hydration never mismatches; after mount it switches to the relative string and refreshes every 60s via `setInterval` (cleared on unmount). See D-13 resolution below |
| Hover | Card hover unchanged. Pill hover fill per Color. No hover-only information anywhere (the `Updated` absolute time on `title` is supplementary; the UTC time is visible text on first paint) |
| Keyboard | Tab order: masthead (none) then the pills in urgency order, then each section's card links in document order, with each expander button immediately after its section's primary grid. Hidden overflow cards and hidden sections are skipped automatically (`hidden`). Visible focus ring on every control |
| Without JavaScript | Server HTML shows all sections, top 6 per section, and inert pills. Accepted limitation for v1: filter and expanders require JS (progressive enhancement is out of scope) |

Last-updated honesty (resolves CONTEXT D-13 caveat): the page is cached about 15 minutes, so a server-computed relative string would freeze at snapshot time. Contract: `getFrontPage()` threads `generatedAt` (ISO 8601 string derived from the same single sampled `now`, per D-09, never a second clock read) into the `status: "ok"` variant of `SectionedFrontPageResult` (and `composeFrontPage`'s return). The relative text is computed on the client from that snapshot timestamp, so it reports the age of the snapshot the viewer is actually looking at and keeps ticking in a long-open tab. The error variant carries no `generatedAt` and renders no bar.

## Accessibility Contract

- Pills: `<button type="button" aria-pressed>` inside `role="group" aria-label="Filter by section"`. Emoji wrapped in `aria-hidden="true"` spans; accessible name includes the count and "articles" via a visually hidden suffix.
- Live region: one visually hidden `role="status"` element announcing the filter result string from the Copywriting Contract. Updated on every toggle.
- Headings: one `<h1 class="sr-only">Latest</h1>` (unchanged), one `<h2>` per section, card titles stay `<h3>`. The filter bar adds no headings.
- Expander: `aria-expanded` + `aria-controls`; the controlled region has the matching `id`.
- Focus: every new control shows `focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-zinc-900 dark:focus-visible:outline-zinc-50`. Pill scroller has `py-1` so this outline is not clipped by `overflow-x-auto`.
- Focus not obscured: `html { scroll-padding-top: 6rem }` (see Spacing exceptions).
- Targets: 44px tall below `md`, 32px at `md`+, never below 24px.
- Motion: none introduced. `backdrop-blur` is static.
- Contrast: AA verified pair list in the Color section must be re-checked in the plan's verification task.
- Text in the bar and headings is always literal constants or numbers derived from the snapshot, never feed-supplied strings.

## Verification Contract (UI-05: real device widths, binding per ROADMAP)

Responsive classes alone do not satisfy UI-05. The plan MUST contain all three tiers:

1. Automated, hermetic (extends `test/productionPage.test.ts` against a production build; no new dependency):
   - `data-section` order still equals `SECTION_DISPLAY_ORDER` and empty sections are absent.
   - For each section, the number of `<article>` elements in the HTML equals the section's total (proves D-07: all cards are in the initial HTML) and, for totals >= 9, exactly 6 sit outside the `data-overflow` region.
   - Totals 1-8 have no `data-overflow` region and no expander button.
   - One `data-filter-pill` per non-empty section, in order, each `aria-pressed="false"` in the initial HTML; pill counts equal the heading counts.
   - Section heading count equals the section's full article count (not the capped 6).
   - Initial HTML contains the `Updated HH:MM UTC` string and no relative-time text for the bar.
   - Page remains statically cacheable: two fetches inside the window are byte-identical (existing assertion kept).
   - Unit tests for `planSectionCap` (totals 0, 1, 6, 7, 8, 9, 10, 26), `formatUtcTime`, and a contrast-pair check for the pill states.
2. Emulated viewport (Chromium mobile emulation with touch and DPR 3, via DevTools device toolbar or ad-hoc `npx playwright`, NOT added to `package.json`): 360x800, 390x844, plus 768, 1024, 1280 and 1440 wide. At every width assert: `document.documentElement.scrollWidth <= window.innerWidth` (no horizontal page overflow); grid columns are 1 / 2 / 3 at the `<md` / `md` / `lg` breakpoints; the pill row scrolls horizontally inside its own container below `md` and wraps at `md`+; the sticky bar stays pinned while scrolling and does not cover focused elements; toggling pills and expanders works with zero network requests (DevTools Network panel or request interception shows none after load); the `Updated` text becomes relative after hydration with no hydration warning in the console.
3. Human check on real hardware: open the Vercel preview deployment on a real iOS (Safari) phone and a real Android (Chrome) phone. Checklist: no sideways scrolling of the page; pills scroll with a thumb and all 7 are reachable; every pill and expander button is comfortably tappable; sticky bar is readable and not too tall; longest live titles (SANS ISC, CSO Online) stay inside their cards; expand/collapse and filter feel instant; both light and dark system themes. Record the devices, widths and result in the phase's verification/UAT artifact.
