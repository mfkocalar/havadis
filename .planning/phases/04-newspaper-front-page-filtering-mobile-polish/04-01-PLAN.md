## Phase Goal

**As a** security expert reading Havadis on a phone or a desktop, **I want to** see the day's articles laid out as a newspaper grid under urgency-ordered sections, with per-section counts and the snapshot's freshness, and narrow it to the sections I care about with one tap, **so that** I can triage what matters without reloading the page or scrolling past sections I don't need.

Framed from the ROADMAP Phase 4 **Goal:** line and its four Success Criteria. That Goal line is not written in user-story form; the orchestrator may run `/gsd mvp-phase 4` to canonicalise it. This story adds nothing the Goal and Success Criteria do not already state.

<objective>
Turn the Phase 3 interim page (one column, every card, no metadata, no filter) into a filterable newspaper front page. After this plan a reader can:
- see a sticky row of count-bearing section pills under the masthead,
- tap pills to narrow the page to one or more sections, entirely client-side,
- read each section as a 1/2/3-column card grid in a 7xl container aligned with the masthead.

This plan owns FILTER-01. It owns the per-section-count half of UI-04, the grid half of UI-01, and the mobile-first structure behind UI-05. It implements D-01, D-02, D-03, D-04, D-08, D-09, D-10, D-11 and D-14.

Purpose: Task 1 is the phase's architectural tracer. It proves the riskiest shape end to end before anything is layered on: server data, then the server page, then a DOM-less client provider, then a client sticky bar, then a client hidden-wrapper around server-rendered sections passed as `children`, served by a production build that stays static at 900 s. Plan 04-02 then adds the freshness timestamp and the "Show all N" expander into the seams this plan creates.
Output: pure filter logic, control class constants plus a real contrast gate, three client units, the reworked `page.tsx` and `layout.tsx`, a focus-offset CSS rule, and production-build invariants.

**Flagged UI-SPEC amendment, needs your sign-off (collected at 04-03 Task 3):** unpressed pills, and the "Show all N" button built in 04-02, use `ring-zinc-500` in both themes. The approved 04-UI-SPEC.md Color section specifies `ring-zinc-400` (light) and `dark:ring-zinc-600`. Those measure about 2.6:1 on white and 2.3:1 on zinc-900, under the 3:1 non-text-contrast target (WCAG 2.1 SC 1.4.11) for a control whose outline is its only visible boundary (04-RESEARCH.md Pitfall 7, Open Question 2). The change stays inside the neutral zinc system. It is enforced by Task 2's contrast gate. Reverting is a one-constant edit (`NEUTRAL_CONTROL_CLASSES`). The executor must record this under "UI-SPEC amendments pending sign-off" in 04-01-SUMMARY.md.

Implementation corrections to UI-SPEC mechanics, with no visual change (04-RESEARCH.md Summary):
- `scrollbar-none` is built into Tailwind 4.3.3, so there is no custom utility block in `globals.css`.
- Accessible names use one visually hidden `, N articles` suffix with the visible count `aria-hidden`, so the section name is not read twice (Pitfall 8).
- Scroll-after-filter runs after a `flushSync` commit rather than in an effect (Pitfall 11).
</objective>
